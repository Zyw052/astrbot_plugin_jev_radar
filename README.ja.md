## ⚠️ プライバシーとコンプライアンス（最初にお読みください）

1. **メッセージ本文が第三者に送信されます**：有効化すると、判定対象メッセージの**テキスト**が HTTPS 経由で **TypeSafe AI**（`api.typesafe.ai`）へ送信され、意図判定が行われます。導入前にデータの機敏性をご評価ください。
2. **越境データの注意**：TypeSafe は海外サービスです。お住まいの地域のデータ規制への準拠をご確認ください。
3. **ローカル匿名化（デフォルト有効）**：送信前に、電話番号／メールアドレス／身分証番号／クレジットカード番号／長桁数字列をプレースホルダーへ置換し、長文は切り詰めます（`max_chars_per_msg`）。
4. **原文は保存しません**：デフォルトでは「判定結果＋メッセージのハッシュ」のみを記録し、元のメッセージ本文は一切保存しません。`log_decisions` はデフォルトでオフです。
5. **完全なオプトアウト**：`enable=false` にすると完全に停止します（監視なし・API 呼び出しなし・通知なし）。`scope_group`／`scope_private`／`group_whitelist` で対象範囲を細かく制御できます。
6. **キーの安全管理**：`api_key` はローカルの `data/config/` にのみ保存されます。ハードコードせず、リポジトリにもコミットしません。取り扱いには十分ご注意ください。
7. **リプライ・コパイロットの追加開示**：コパイロットを有効にすると、匿名化済みメッセージ本文が ①判定時に TypeSafe へ、②下書き生成時にホスト AstrBot の LLM Provider へ送られます。候補リプライは**オーナーにのみ送付**され、元の会話へは決して送信しません。

## ① プラグインの概要と位置づけ

[TypeSafe SystemOne（Jev）](https://typesafe.ai) の typed decision 機能を利用し、グループ／個人チャットのメッセージをリアルタイムで **「意図ラベル＋感情傾向＋リスクレベル＋確信度」** に判定します。設計は極めて控えめに設計されており、低確信度または高リスクの場合にのみ注意喚起し、画面を流すことは決してありません。

> ひとことで言えば：**AstrBot には公式の Jev「ゲート（reply_gate）」があり、本プラグインは Jev の「目」です。**
> 公式 `reply_gate` は「Bot が返信すべきか」を判断し、本プラグインは「**人間がこのメッセージをどう読むべきか**」を出力します。役割が異なるため、併用できます。

主な機能：

- **パッシブモード**（デフォルト無効）：メッセージを自動監視し、高リスク／低確信度／注目意図の時にのみ通知します。
- **アクティブモード**：`/jev` で随時判定、`/jev dry` で試し実行。
- **リプライ・コパイロット**（デフォルト無効）：Jev が審判、ホスト LLM が文章化。オーナー向けに候補リプライを起草します。代わりの送信は決して行いません。

## ② インストール

1. 本プラグインのディレクトリを AstrBot の **`data/plugins/`** 配下に置きます（ディレクトリ名 `astrbot_plugin_jev_radar`）。
2. 依存関係は **`aiohttp>=3.9`** のみです（`requirements.txt` 参照）。プラグイン追加時に AstrBot が自動でインストールします。入っていない場合は `pip install aiohttp>=3.9` を実行してください。
3. WebUI の「プラグイン管理」で**有効化／再読み込み**します。
4. プラグイン設定に **TypeSafe API Key** を入力します（<https://console.typesafe.ai> で取得できます）。
5. （任意）`passive_enabled=true` でパッシブモードを有効にします。

> Jev は**テキストのみ**を判定します。画像・音声・動画には対応していません。

## ③ 設定項目の詳細説明

`_conf_schema.json`（27 項目）に対応。「**効果**」は各設定が実際に何を変えるかを示し、「推奨値」は一般的な目安です。

| 設定項目 | 型 | 既定値 | 効果 | 推奨値 |
|---|---|---|---|---|
| `enable` | bool | `true` | マスタースイッチ。無効時は監視・API 呼び出し・通知のすべてが停止 | 既定のまま |
| `api_key` | string | `""` | TypeSafe API キー。ローカル保存のみ。**空欄では呼び出し不可** | 必須 |
| `base_url` | string | `https://api.typesafe.ai` | API エンドポイント。実際は `POST {base_url}/v1/systemone` を送信 | 既定のまま |
| `model` | string | `jev-latest` | Jev モデル名（`jev-preview` も利用可） | `jev-latest` |
| `timeout_sec` | int | `20` | 1 リクエストあたりのタイムアウト秒数。回線が遅い場合は増やす | 20〜30 |
| `retries` | int | `1` | 429／503／529（レート制限・過負荷）のみリトライ。その他のエラーは即時に失敗 | 1 |
| `confidence_threshold` | float | `0.75` | 意図の確信度がこの値未満なら「要確認」とし、パッシブモードで通知対象に | 0.75 |
| `risk_alert_threshold` | int | `2` | リスクレベル 0=安全／1=注意／2=高危険。この値以上で通知を発火 | 1（敏感）または 2 |
| `daily_call_limit` | int | `2000` | 1 日あたりの判定呼び出し上限。0=無制限。費用ガード | 2000 |
| `passive_enabled` | bool | `false` | パッシブモードのマスタースイッチ（デフォルト無効：迷惑・コスト防止） | 必要時のみ有効化 |
| `scope_group` | bool | `true` | パッシブモードでグループメッセージを処理するか | 既定のまま |
| `scope_private` | bool | `false` | パッシブモードで個人チャットを処理するか | 既定のまま |
| `group_whitelist` | list | `[]` | パッシブモード用のグループホワイトリスト。**空欄=全グループ対象** | 複数グループ参加時は絞り込みを推奨 |
| `watch_intents` | list | `["推销","引战","诈骗","拉人"]`（売り込み・煽り・詐欺・勧誘） | 「注目意図」の一覧。パッシブモードで命中した場合は高確信度でも通知が発火 | 必要に応じて編集 |
| `desensitize` | bool | `true` | 送信前のローカル匿名化（電話番号・メール・身分証・カード・長桁数字） | **常に有効推奨** |
| `max_chars_per_msg` | int | `800` | 長文はこの長さで切り詰めてから送信（費用＋プライバシー） | 800 |
| `result_style` | string | `詳細` | `詳細`=確信度付き複数行。`簡潔`=一行サマリー | お好みで |
| `log_decisions` | bool | `false` | 判定結果をローカル `decisions.jsonl` に記録（ハッシュのみで**原文は含まない**）。有効でないと `/jev_stats` の履歴統計が出ません | 統計が必要なら有効化 |
| `reply_copilot_enabled` | bool | `false` | リプライ・コパイロットのマスタースイッチ。有効時でも `trigger_mode` に従ってのみ発火 | 必要時のみ有効化 |
| `trigger_mode` | string | `explicit` | `explicit`=オーナーの `/reply` コマンド時のみ（最も控えめ）；`risk`=ホワイトリスト会話内で、Jev が注目意図／高リスクかつ十分な確信度と判定したときに起草してオーナーへ通知 | `explicit` 推奨 |
| `draft_count` | int | `3` | 1 回の起草で生成する候補リプライの数（2〜3） | 3 |
| `draft_style` | string | `concise` | `concise`=簡潔率直／`polite`=丁寧／`firm`=毅然 | 用途に応じて |
| `cooldown_minutes` | int | `10` | risk モードで同一会話内の LLM 起草の最短間隔（分）。0=クールダウンなし（非推奨）。費用ガード | 10 |
| `max_drafts_per_day` | int | `20` | 1 日あたりの LLM 起草上限（0=無制限）。Jev の判定はこの件数とは**別集計**で相互に食い込みません | 20 |
| `notify_target` | string | `""` | risk モード時に候補リプライを**プッシュする先**のオーナー会話識別子（UMO、例：`aiocqhttp:FriendMessage:xxxx`）。空欄なら記録のみでプッシュせず | risk モード使用時は必須 |
| `copilot_whitelist` | list | `[]` | risk モードが有効になる会話のリスト（UMO またはグループ番号）。**空欄=risk モードは一切発火しません**（最も控えめ） | risk モード使用時は必須 |
| `llm_provider_id` | string | `""` | 起草に使う LLM Provider。空欄=現在の会話の既定 Provider | 既定のまま |

## ④ コマンドマニュアル

### `/jev` — 手動判定
- **用途**：テキストを「意図／感情／リスク／確信度」に判定します。
- **引数**：任意の `dry` と判定対象テキスト。または**メッセージを引用返信**して引数なしの `/jev` を送ると、引用したメッセージを判定します。
- **例**：
  ```
  /jev お姉さん、うちのパックは天然成分で、今日が最終日、先着50名にマスク器プレゼント！
  ```
  出力例：
  ```
  🎯 Jev インテント・レーダー
  意図：売り込み（確信 1.00）
  感情：中立（0.90）
  リスク：高危険 ⚠️（0.95）
  ```
- **dry 実行（試し実行）**：`/jev dry 兄弟、今空いてる？5000 貸してくれないか、来月返すよ。` のように実行すると「送信予定の内容」を表示するだけで、送信も記録も行いません（ただし**判定APIの1回は消費します**）。別名 `/jev test`。`/jev stats` は `/jev_stats` の利用を促す案内を表示します。

### `/jev_stats` — 利用状況と統計（別名：`雷达统计`／`radar_stats`）
- **用途**：本日の判定呼び出し枠（コパイロット起草分を含む）、判定履歴の総件数、意図分布 Top5、リスク分布を表示します（v1.2.0 の新機能）。
- **引数**：なし。
- **例**：`/jev_stats`
- 注意：`log_decisions` が無効のときは履歴分布データがなく、有効化の案内が表示されます（本日の枠は常に確認可能です）。

### `/reply` — 候補リプライの起草
- **用途**：ホスト LLM が現在の文脈に基づき候補リプライを 2〜3 件起草します（それぞれに「なぜこう返すか」を一行添付）。参考用であり、**どの会話にも代わりに送信することはありません**。
- **引数**：任意のテキスト。または**メッセージを引用返信**して `/reply` を送ると、そのメッセージへの返答を起草します。
- **例**：
  ```
  /reply 相手がまた発送を催促してきて、口調がきつい
  ```
- 前提：`reply_copilot_enabled=true`（デフォルト無効）。`risk` モードではコマンド不要で、注目メッセージが自動的に起草を発火し、`notify_target` へプッシュします。

## ⑤ パッシブ監視の仕組み

- 実装：AstrBot の `@filter.event_message_type(EventMessageType.ALL)` で全メッセージを受け取り、`on_llm_request` フックで設定を確認した上で必要なときだけ API を呼び出します。
- **デフォルトでは無効**（`passive_enabled=false`）：チャットへの妨害と予期せぬ API 費用を避けるためです。
- **有効化の方法**：プラグイン設定で `passive_enabled=true` にして再読み込みしてください。
- **適用範囲**：`scope_group`（グループ、既定有効）× `scope_private`（個人チャット、既定無効）× `group_whitelist`（空=全グループ）の積集合です。
- **通知条件（以下のいずれか 1 つに該当したときのみ通知し、それ以外は静かに記録）**：
  1. 意図の確信度が `< confidence_threshold` 未満（「要確認」表示）；
  2. リスクレベルが `>= risk_alert_threshold`；
  3. `watch_intents` の注目意図に該当（高確信度でも通知）。
- **注意点**：①有効化すると列単位で費用が発生するため `daily_call_limit` との併用推奨。②まず dry 実行や短いホワイトリストで小さく検証を。③パッシブ通知はオーナーの会話にのみ届き、元の会話へは決して表示されません。

## ⑥ KV クォータと統計

- **クォータの永続化**：本日の判定回数（`daily_usage`）とコパイロット起草回数（`reply_draft_usage`）は AstrBot の KV ストア（`data/plugin_data/` 配下）に永続化され、再起動後も引き継がれます。
- **2系統の予算は別集計**：低コストの Jev 判定は `daily_call_limit` に、高コストの LLM 起草は `max_drafts_per_day` にカウントされ、互いの枠を消費しません。
- **読み書き失敗時の警告**（v1.2.0）：KV の読み書きに失敗すると**警告ログを出力**し、一時的にメモリ計数へフォールバックします（この場合、再起動でその日の件数はリセットされます）。これまでの静かな喪失を改め、切り分けを容易にしました。
- **`/jev_stats` の表示内容**：本日の判定件数 X ／上限 Y、本日の起草件数 A ／上限 B、判定履歴の総件数、意図分布 Top5、リスク分布。履歴分布は `log_decisions=true` が必要です。

## ⑦ FAQ

1. **導入したのに反応しません。** 順にご確認ください：`api_key` を登録済みか → `enable` が true か → パッシブモードなら `passive_enabled=true` かつ `scope_group`／`scope_private` の少なくとも一方が有効か、対象グループが `group_whitelist` に含まれているか。接続確認には `/jev こんにちは` が便利です。
2. **通知がまったく来ませんが？** 仕様です。パッシブモードは低確信度／高リスク／注目意図のときにのみ通知し、日常会話は沈黙します。感度を高めたい場合は `risk_alert_threshold` を 1 に下げる、`confidence_threshold` を上げるなど調整してください。
3. **クォータ／コストはどう管理するのですか？** `daily_call_limit`（既定 2000）が判定を、`max_drafts_per_day`（既定 20）と `cooldown_minutes`（既定 10）が LLM 起草を枠止めします。使用量は `/jev_stats` で随時確認できます。パッシブモードは既定オフのため、意図しない支出を防ぎます。TypeSafe は input token 単位の課金のみ（約 $0.042/Mtok）で、1回の判定コストは1セント未満の極小値です。正確な価格は公式ドキュメントをご確認ください。
4. **ログや記録はどこにありますか？** 動作ログは AstrBot コンソールへ。判定記録（結果＋メッセージハッシュのみで原文なし）は `log_decisions` を有効にすると `data/plugin_data/` 配下の `decisions.jsonl` に出力されます。KV クォータの読み書き失敗はログに警告行として記録されます。
5. **完全に止める／削除するには？** 完全停止：設定で `enable=false`（監視・呼び出し・通知すべて停止）。削除：WebUI のプラグイン管理から削除し、`data/plugins/astrbot_plugin_jev_radar` ディレクトリを消してください。パッシブのすべての監視はスイッチで即時に停止します。
6. **`/reply` が「起草失敗」と返してきます。** ホスト LLM の呼び出しが失敗しています（タイムアウト・未設定・枠の消費など）。コマンドはエラー概要を表示し、他の機能への影響はありません。ホストの LLM Provider や `llm_provider_id` をご確認ください。
7. **画像や音声も判定できますか？** できません。Jev はテキストのみを判定し、画像・音声・動画メッセージは無視（または非テキスト扱い）されます。

## ⑧ プライバシーとコンプライアンスのアドバイス

- 匿名化済みメッセージ本文は判定のために TypeSafe（海外）へ、コパイロット有効時はさらにホスト LLM Provider へ送られます。本プラグイン作者のサーバーへ送信されることは**ありません**。作者は一切データを収集しません。
- `desensitize=true`、`max_chars_per_msg=800`、統計に必要な場合を除き `log_decisions=false` を保ち、パッシブモードはホワイトリスト内に限定することを推奨します。
- 現地の個人情報保護法制（越境移転規制など）に照らして利用用途をご評価ください。
